Side dock — elevation, as built

Surface: the compact transcriber's second presentation (window label hud-dock). Date: 2026-08-10. Branch: hud-side-dock.

Built, and measured. Every number below is getBoundingClientRect() against the running window rather than a reading of the stylesheet, taken through scripts/Invoke-WebviewProbe.ps1 -Window dock. The specification this amends is The side dock in docs/UI-GUIDE.md. A drawing goes stale the moment apps/desktop/src/styles.css moves.

Before and after, at 1:1

The 360 pixels

Height Row What it holds
20px .hud-dock-chrome The close button. This window is undecorated, so this strip is its whole titlebar.
86px .hud-dock-wordmark Vertical, set sideways as a unit the way a spine label is.
152px .hud-dock-level 21 rows of 3px on a 3px gap = 123px of waveform, centred. The one row that flexes, and the same height in every state.
16px .hud-dock-clock Elapsed, while a dictation is running. Empty otherwise, never absent.
28px .hud-dock-action Stop, while a dictation is running. Empty otherwise, never absent.

5px window gutter × 2 = 10, leaving a 120×350 card. 8px card padding × 2 = 16, four 8px gaps = 32, fixed rows = 150. 198 + 152 = 350. Measured on the running window: card 122×350, rows 20 / 86 / 152 / 16 / 28, no overflow on either axis. The card is 122 rather than 120 because Windows floored the declared 130 window width to 132 on this display — the card is sized in percentages precisely so that floor lands in one place instead of two.

Solid: as built — seated 24 logical pixels in from the work area's edge, clamped so its bottom stops at the work area's bottom. Faded: the same drop clamped against the full display instead, which is where it used to land — 48 physical pixels of it behind the taskbar, on a window that is alwaysOnTop and skipTaskbar and so has nothing to click to get it back.

Change ledger

What Was Now, and why
Wordmark Upside down writing-mode alone. The stacking and the 180° rotation were both removed; either one alone was survivable, together they inverted it.
Level meter A <meter> fill in an 18px column A symmetric waveform, newest sample in the middle. The <meter> is still there, visually hidden, carrying the value and the accessible name.
Meter at rest Nothing A grey rail. Blank was the honest answer for the default HUD's fill; on 122px of otherwise empty card it just read as broken.
Stop Absent by design Present. Hands-free is one of three hotkey activation modes and has no key that ends a recording.
Height 240 360 — the elevation's proportion had to come from this axis, because 130 is a measured width floor rather than a choice.
Corners and window Square, opaque 14px radius on a transparent window, inset 5px. Both documents above the card need background: transparent — :root paints --surface, and that light rectangle was showing through the corners.
Shadow None A 5px cast shadow plus an inset hairline. The 20px blur this was first drawn with was clipped to nothing by the window edge in the running build.
Edge Flush, full display 24 logical px in, against the work area.
130 declared width 130 130 — unchanged, and still a measured floor rather than a design choice.

Two defects only the running window showed

  • The card sized itself to its contents. height: 100% resolves against #root, whose own height is auto — so the card came out 321px tall inside a 360px window, with the 29px shortfall showing through as transparent desktop under the Stop button. The stylesheet reads as if it should work. It is calc(100vh - var(--dock-gutter) * 2) now.
  • The drop shadow was invisible. A cast shadow can only render into the gutter body reserves, and 5px of gutter cannot hold a 20px blur. The card read as pasted onto the desktop.
